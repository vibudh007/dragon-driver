# Vendor profile XML

`Profiles::default()` builds the `Parameters` root with index 1. `from_xml(bytes)` parses UTF-8-compatible XML into a bounded element tree, retaining unknown children, attributes, text and comments. It rejects DTDs and limits input length, nesting, total nodes, and attributes per element. `to_xml()` serializes through the XML writer, escapes text and attributes, and uses `validate_xml_text` to reject forbidden XML 1.0 characters. It can normalize whitespace and document-level nodes. File opening and saving belong to callers, so a failed parse or edit has no disk side effects.

| Rust operations | Vendor behavior |
| --- | --- |
| `profile_index`, `set_profile_index` | Read or replace root `profileIndex`. Missing attribute uses 1. |
| `append_profile` | Appends a full configuration in vendor child order. See defaults below. |
| `profile`, `contains`, `list_profiles` | Read indexed profile data. Listing uses ascending numeric order. |
| `rename_profile`, `remove_profile` | Rename clears both app-association attributes. Remove deletes the matching node. |
| `export_profile`, `import_profile` | Copy the selected profile node into a destination. Optional export increment and import's next numeric index follow the vendor. Arithmetic overflow fails without changing the destination. |
| `function_settings`, `set_function_settings` | Read or replace the four text-valued `Setting` attributes. |
| `sleep_settings`, `set_sleep_settings` | Read or replace the two signed decimal sleep values. |
| `light_using_index`, `set_light_using_index`, `keyboard_light_status`, `set_keyboard_light_open`, `set_keyboard_light_sync` | Read or change the selected bank or keyboard XML attributes. |
| `lights`, `add_light`, `modify_light` | Read, append or update lighting records typed by bank and mode. `LightItem::from_node` and `write` translate the 14 decimal attributes. |
| `contains_light_mode` | Check a bank for a child with the requested decimal `ledType`. Missing parents and absent modes return false. |
| `append_macro`, `macro_events`, `append_macro_events` | Create a macro and store its six text event fields in order. |
| `advanced_document`, `dks_stroke_values`, `set_dks_stroke_values` | Create the DKS, Mod-Tap and Toggle containers, or read and write four DKS thresholds. |
| `advanced_items`, `append_advanced_item`, `modify_advanced_item`, `remove_advanced_item` | Use distinct typed actions for the three advanced-key payloads. `AdvancedKind::container` and `AdvancedAction::kind` select the XML container. `AdvancedAction::write` preserves the per-kind attribute shape. |

Internal helpers: `Element::new` creates a node. `attribute` and `set` read or update attributes without reordering existing attributes. `append` adds a child, `elements` and `elements_mut` iterate element children, and `child` and `child_mut` find the first named child. `replace_child` removes the first matching child and appends the new one, matching the vendor's replacement order. `write_xml` serializes a subtree. `config`, `config_mut`, `indexed`, `advanced_index`, `profile_info`, and `remove_indexed` implement profile and record selection. `decimal` parses the signed numeric prefix as the DLL does for ordinary values and bounds overflow. `invalid_xml` wraps parse failures as invalid data.

At `0x1001d130`, the default profile sets all light banks to `usingIndex=2`, the keyboard light state and sync to zero, and linked side status to zero when requested. The four features are `0,0,0,1` and the sleep settings are `600,30`. The advanced configuration at `0x100262a0` sets DKS thresholds to `15,36,36,15`. The values come from x86 stack arguments to `FUN_10013a10` that Ghidra omits from the call display.

See [custom records](profile/custom.md) and the DLL parity tracker. The offline tests compare profile defaults and onboard imports with [XML generated by the original DLL](../../tests/fixtures/vendor-sdk/README.md). The [onboard imports](profile/bulk.md) interpret legacy device buffers. `contains_advanced_index` searches DKS, Mod-Tap, and Toggle containers in vendor order.

`with_advanced_definitions` adds the existing vendor advanced-key containers to a profile workspace for GTK export. `advanced_definitions` copies those containers into a standalone advanced document and preserves the identifiers referenced by the key assignments.

`set_profile_application` updates the vendor app association and stores Linux StartupWMClass when supplied. `profile_x11_class` reads that optional native field. `remap_switch_targets` validates and updates profile-switch indices when the GTK import allocates new indices.

`contains_advanced_index` scans all existing advanced sections. Imported documents may omit sections while retaining the index namespace shared by the remaining definitions.
