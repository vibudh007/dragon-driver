# Keyboard session and replies

`Keyboard::open` queries identity using a single nonblocking descriptor and continues using that descriptor. It requires a known vendor model and a matching configuration collection. Hall-effect controls additionally require vendor device type 4. The SDK validates the descriptor and sysfs data during open. Dropping the keyboard closes the descriptor.

`read_key`, `read_control`, `read_lighting`, and `read_sleep` issue one typed request and decode its response. `query` uses the report collection's expected ID and a one-second timeout. `exchange` drains at most 128 queued reports before the write and skips unrelated or truncated replies until the deadline. The protocol's missing transaction identifier means late matching replies cannot be distinguished from new ones. A transport error or timeout requires a fresh session. A separate process with access to the same USB device can still affect state.

`apply`, `set_control`, `set_lighting`, and `set_sleep` send settings through the SDK framer. `ensure_region` checks side lighting support before I/O. The send result confirms a complete HID transfer. Apply performs no implicit retries and requires a separate read to learn the device's resulting settings. `ensure_ready` prevents reuse after a transport failure. `disable_rapid_trigger` switches to the vendor’s mode 0 and verifies that both original actuation thresholds remain unchanged. A key with unequal thresholds requires an explicit shared threshold choice. `set_static_color` switches the keyboard region to the vendor static effect, replaces its foreground RGB, and reads back both fields.

The private `Transport` adapter owns no descriptor. It forwards reads and readiness checks to HIDRAW and checks full writes. Tests inject a scripted transport for stale, mismatched and short reports, timeouts, and the single-write rule. EXE worker

## Additional workflows

- `actuation_limit` reads the vendor selector-4 limit and validates that it is positive. `read_lighting_modes` requests the mode catalog and checks the delimiter and remaining bytes. `Received` preserves the actual read length so variable-length decoders cannot consume unwritten bytes.
- `read_link_status` queries the EXE handshake status and returns battery, transport and receiver fields. USB audio checks the returned transport before entering synchronization.
- `calibrate` starts a one-key or all-keys calibration and returns a guard that exclusively borrows the session. `Calibration::progress` waits for events of the selected operation until the supplied deadline. `stop` leaves the operation and reports I/O errors. Dropping the guard attempts the same cleanup. Calibration changes recorded by the device are separate from leaving calibration mode.
- `upload_profile` checks the target layout and runs its complete prevalidated plan. `execute_profile` preserves packet order, pauses at the two vendor timing boundaries, retries each macro packet up to four total transmissions while waiting for report `0x19`, and observes download status from report `0x01`. The return distinguishes transmission from explicit device acceptance. An I/O error or rejected status can leave a partially uploaded profile. The opaque profile plan is generated before any device change.
- `preview_custom_colors` sends the vendor’s page-2 custom RGB frame. `apply_custom_colors` validates the preset, writes the selected page, waits 5 ms and sends the vendor's activation packet. A failed transfer can leave part of the color page changed. `send_wireless_lighting` sends a typed 2.4 GHz update with optional side data. `stream_usb_audio` consumes little-endian mono PCM from a caller-provided reader, sends wired lighting frames, and attempts to leave synchronized mode even after an I/O error. `read_pcm_window` handles partial reads and incomplete samples.
- `set_sleep` waits for the vendor's success acknowledgement. `set_shortcut_lock`, `reset_settings`, and `reset_magnetic_settings` expose their explicit write operations. `set_gamepad_mode` requires a vendor gamepad product ID and closes the session to further operations because the USB device can re-enumerate.
- `write_direct_mapping` sends an explicit vendor six-key, full-key, multimedia, or mouse-button remap for callers that use these single-report paths. The caller selects the mapping appropriate for its model and operation. [Remap codecs](transfer.md)

`monitor_travel` selects one populated Hall-effect position and starts an exclusive live session. `TravelMonitor::next_reading` ignores other positions and waits up to the supplied duration. `stop` or drop leaves live monitoring. The GTK app displays the raw sample because its units have yet to be checked on hardware.

`upload_profile` installs a snapshot of desktop bindings only on explicit device acceptance. `poll_desktop_binding` reads a bounded idle batch and returns an action from that snapshot. `discard_pending_bindings` lets the worker discard events that arrived during another operation so they cannot trigger later. Reset and gamepad changes clear the map.

`stream_wireless_lighting` checks the link, reads the stored preset and applicable side-light settings, then streams until the caller cancels. Reactive effects read events from the matched keyboard. `stream_audio` chooses the wired frame or receiver spectrum transport from the live link status. `stream_audio_for` shares the FFT, frame pacing, and cleanup, while `wireless_bands` reduces adjacent pairs to the second band and maintains decaying peaks. `with_lighting_sync` exits synchronization after normal completion or an I/O failure. [Wireless renderer](wireless.md)

`recover_reads` reopens a desynchronized session and verifies that its interface and identity are unchanged. It preserves working sessions and does not reopen a session that still owns desktop bindings. It never retries the operation that failed.

`show_wallpaper_lighting` sends one per-key frame through the shared wired RGB stream. `begin_wallpaper_lighting` checks the wired link, saves the current effect, and verifies Custom before enabling synchronization. `keep_wallpaper_lighting` sends only the synchronization report every 500 ms. The related 7186 firmware clears synchronization after about 1.5 seconds, and either a synchronization or an RGB report resets that timer. The Windows driver's three-second synchronization interval accompanies continuous RGB updates. `stop_wallpaper_lighting` releases synchronization and restores the preceding effect with the latest brightness. Cleanup is attempted on transfer failure, session recovery, or drop. The GUI skips effect observations while the daemon owns a reactive effect. Wallpaper colors never write a saved palette slot. [Wallpaper controls](../ui/controls/reactive.md) · Related firmware watchdog · EXE timer

`stream_audio_bars` consumes bounded 22-byte bar frames from the daemon and writes changes directly on the keyboard worker, bypassing palette edit debounce. USB uses the temporary Custom stream, a separate synchronization keepalive, and a four-color key frame. Compatible receivers carry eleven paired heights and peaks and render their own colors. Cancellation or I/O failure exits synchronization and restores the previous wired effect. [Audio controls](../ui/controls/reactive.md)

`open_broker_file` uses a verified descriptor already held by the desktop broker and identifies the keyboard before replaying saved settings. `write_custom_page` uploads a custom page with the existing transfer delay. `restore_effect` writes the intended effect and checks mode and brightness readback.
